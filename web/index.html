2️⃣ Matriz de Clasificación con Switches Segmentados

Clasifique cada uno de los 6 enunciados técnicos seleccionando el switch binario correspondiente.

📖 Dónde estudiar este tema en la bibliografía
Diapositivas Unidad 5: Tipos de Sistemas Operativos (Slide 8), Estrategias de Conexión y Contienda (Slides 25-26), Grupos Cerrados vs Abiertos (Slide 32), Grupos Compañeros vs Jerárquicos (Slides 33-35), Membresía de Grupo (Slide 36).
1. Visibilidad y Gestión Global de Recursos El usuario no distingue si un archivo o proceso está local o en otra máquina; el SO gestiona memoria y CPU de forma global.
2. Origen del Mensaje en Comunicación Grupal Cualquier proceso externo que no pertenezca al grupo puede enviar solicitudes o datos a la dirección del grupo.
3. Estructura de Proceso Coordinador y Trabajadores Un nodo centralizado toma decisiones, asigna tareas y despacha trabajos, constituyendo un punto único de fallo (SPOF).
4. Estrategia de Conexión de Datos Los mensajes se dividen en paquetes independientes que pueden seguir distintas rutas y comparten los enlaces físicos.
5. Técnica de Resolución de Contienda en Bus El nodo escucha el canal antes de transmitir; si detecta una colisión simultánea aborta la transmisión y espera un tiempo aleatorio.
6. Administración de Membresía de Grupos Existe un servidor dedicado que centraliza altas, bajas y consultas de miembros del grupo de forma rápida y directa.

4️⃣ Flujo Secuencial de una Llamada RPC (Remote Procedure Call)

Ordene cronológicamente las 6 etapas del ciclo de vida de una llamada RPC arrastrando cada tarjeta a su posición correspondiente.

📖 Dónde estudiar este tema en la bibliografía
Andrew S. Tanenbaum: Capítulo 2 (Comunicación entre Procesos: Remote Procedure Call). Diapositivas Unidad 5 (Slide 13, 20 y 27). Etapas: Invocación del cliente -> Client Stub empaqueta (marshaling) -> Envío por red -> Recepción en servidor -> Server Stub desempaqueta (unmarshaling) -> Servidor ejecuta y retorna resultado.
💻 El proceso cliente invoca localmente la función llamando al Client Stub
📦 El Client Stub empaqueta los parámetros en un mensaje de red (Marshaling)
📤 El kernel del cliente transmite el paquete de red hacia el nodo servidor
📥 El kernel del servidor recibe el paquete y se lo transfiere al Server Stub
📬 El Server Stub desempaqueta los parámetros (Unmarshaling) y llama a la rutina
🖥️ El servidor procesa la operación y devuelve la respuesta por el Server Stub
